# ciplink-tagserver 0.3 / @ciplink/react 0.3: design

This release adds typed tags, write intent, momentary buttons and derived values to the tag server.
The server stays the base: one thread per PLC, tiers, learned pages, the packet planner, token auth.
Structure (tags, types, UDTs) always comes from the controller. Intent (what may be written, limits, units,
deadband, bit names, poll rates) comes from TOML rules. Nothing is declared twice.

Requires ciplink 0.2 (`Tag.error_kind`, `ErrorKind`, `TagError`, strict write values,
`LogixDriver.get_tag_descriptions`). Pin `ciplink>=0.2,<0.3`.

## 1. Patterns

Every pattern (rules, poll groups, token write patterns) uses one matcher, `rules.match(pattern, name)`:
case-insensitive, `*` matches any run of characters (including `.` and `[]`), `?` one character, everything
else literal. `[` and `]` are literal (so `Tank[*].Level` matches `Tank[3].Level`), unlike fnmatch.
Rule and group patterns match the tag path inside its PLC (`Tank[3].Level`, `Program:Bench.Mode`);
token write patterns keep matching qualified names (`PLC1/Bench.SpeedSP`).

## 2. Rules

```toml
[[plc.PLC1.rule]]
match    = "Bench.SpeedSP"
writable = true        # the tag is a setpoint; writes also need a token write pattern
min      = 0
max      = 1800
units    = "rpm"
description = "Spindle speed setpoint"   # optional, else the controller description if ciplink can read it

[[plc.PLC1.rule]]
match    = "Bench.Speed"
deadband = 0.5         # numeric changes smaller than this (vs the last PUBLISHED value) are not sent
units    = "rpm"

[[plc.PLC1.rule]]
match    = "Bench.StatusWord"
always   = true        # read at tier 1 even with no subscribers (alarms, logging)
bits     = { EStop = 0, DoorOpen = 1, Fault = 2 }   # names for integer bits: Bench.StatusWord.EStop

[[plc.PLC1.rule]]
match    = "Bench.Recipe"
together = true        # members of this struct are always read in one read (no torn values across scans)
```

- Several rules can match one tag. For each field, the first rule (file order) that sets it wins. So put
  specific rules first.
- `rules.effective(plc, tag) -> dict` returns the merged fields (memoized).
- A bit alias `X.Name` is resolved to `X.<n>` by the server wherever a tag name comes in (sub, write,
  momentary), using the `bits` of the rule that matches `X`. Clients may send either form; values and
  acks are keyed by the name exactly as the client sent it.

## 3. Poll groups

```toml
[[plc.PLC1.group]]
name    = "fast"
rate_ms = 50
match   = ["Bench.Axis.Position", "Bench.Axis.Velocity"]

[[plc.PLC1.group]]
name    = "slow"
rate_ms = 2000
match   = ["Tank[*].Temp"]
```

- A group overrides the polling rate of a tag **only while the tag is at tier 1**, which means some loaded
  page shows it, or it is `always`. At tier 2 or 3 the group is ignored and the tag follows the normal tier
  rules, because faster polling of a tag nobody is looking at is wasted.
- First matching group wins. Tags in no group are read every `cycle_ms` at tier 1, as today.
- The worker loop ticks at the smallest rate among `cycle_ms` and the groups that currently have tier-1
  tags. Each tick reads the tags that are due. A tag's due time is `last_read + rate`; a group tag due in
  the same tick as cycle tags is read in the same `plc.read` (same packets). The tier-2 round-robin slice
  advances only on ticks that are `cycle_ms` boundaries.
- Overruns are counted per tick. `/stats` adds `groups: {name: {rate_ms, tags, last_period_ms}}`.

## 4. Worker changes

- **Deadband**: when a numeric value's change from the last published value is smaller than the deadband,
  the cache keeps the new value but nothing is published. A quality change always publishes.
- **Quality from error kinds** (`values.quality(tag)` uses `Tag.error_kind`, never message text):
  `None` -> `good`; `not_found`, `access` -> `missing` (value None); every other kind -> `bad`, which
  **keeps the last good value**, so a screen shows the last value marked bad instead of `--`.
  `refused` and `table_changed` are transient: the cycle simply retries next time.
- Cache entries become `[value, quality, t, error]` where `error` is `null` when good, else
  `{"kind": "...", "message": "..."}`. Wire entries are the same 4-tuple. Old clients ignore the 4th element.
- **Writes between packets**: `planner.execute` gains a `between` callback. The worker splits a cycle's
  reads into chunks of one estimated packet each (`planner.packets()` already models this) and calls
  `plc.read` once per chunk, draining the write queue between chunks. A write waits at most one packet
  (about 15 ms) instead of a whole cycle. Each `plc.read` adds no extra packets: ciplink puts the version
  check into every packet anyway.
- **Read-back**: after a successful write, the worker reads the written tag back right away (for a bit
  write, its word) and publishes it. The write's future gets `(ok, error, kind, readback_value)`.
- **always**: tags whose effective rule has `always = true` are added at tier 1 by the hub at startup and
  after each tag table reload, under an internal reference that never releases. They are only polled if the
  tag exists (see the tag list).
- **Descriptions**: after connect and each reload, if the driver has `get_tag_descriptions`, the worker reads
  descriptions for the tags in the tag list lazily: only when a tag is first subscribed. It caches them per
  tag table version. A rule `description` wins. Failure is not an error: no description.

## 5. Writes (hub)

Order of checks, all before anything is queued. The ack `error` is a string and `kind` is a string:

1. The name qualifies and the alias resolves (else `kind: "bad_request"`).
2. A token write pattern matches the qualified name (else `kind: "not_allowed"`, `error: "not allowed"`).
3. The effective rule has `writable = true` (else `kind: "not_writable"`). **Breaking:** the token pattern
   alone no longer allows a write. The README and release notes say so, and the example configs add rules.
4. For numbers (and each number in a list or dict), check `min`/`max` (else `kind: "out_of_range"`).
5. Type and size: ciplink 0.2 rejects them per tag (`kind: "bad_value"`), with nothing sent.

The ack becomes `{"op":"ack","id":..,"ok":..,"error":..,"kind":..,"value":<read-back value or null>}`.
`kind` is null on success.

**Audit**: one JSON line per attempt: `time`, `token`, `tag` (qualified), `old` (cache value before the write,
or null), `value`, `ok`, `error`, `kind`. Lines are written off the event loop by one background thread with a
queue, never blocking the loop.

## 6. Momentary

`{"op":"momentary","id":n,"tag":"Bench.StartPB","action":"press"|"hold"|"release"}`

- Only for BOOL tags or integer bits, and the same checks as a write (token pattern plus writable rule).
- `press` writes true and acks like a write. `hold` refreshes the watchdog and is not acked. `release` writes false
  and acks.
- Watchdog per (session, tag): with no `hold` or `press` for `momentary_timeout_ms` (server config, default
  1000), the server writes false itself. When a session closes, all its pressed tags are released.
  Clients send `hold` every 300 ms while pressed.
- Audited like writes, with `value` true/false and `"momentary": "press" | "release" | "timeout" | "disconnect"`.

## 7. Session output

- Values are coalesced: each session keeps `pending: {client name: entry}` and one control-message queue.
  The sender task always sends the queued control messages (ack, info, status, meta, error) in order, then
  one `values` message with everything pending, then clears it. A slow client skips intermediate values but
  never ends up stale and never grows memory without bound. Snapshot values after a `sub` go through `pending` too.
- The hub keeps an index `subscribers: qname -> {session: client name}`, so fan-out does not scan every
  subscription for every change.

## 8. Tag info

The first time a session subscribes a name, the server sends
`{"op":"info","d":{name:{"type":"REAL","writable":true,"min":0,"max":1800,"units":"rpm","deadband":0.5,"description":"...","bits":{"EStop":0},"rate_ms":250,"group":null}}}`
(only fields that apply; `type` from the controller tag list, null if unknown). It is sent before the snapshot
values. Bit names resolve to type `BOOL`.

## 9. HTTP

- `GET /tags?plc=` (bearer auth) returns
  `{plc, state, version, tags: [{name, type, dims?, aoi_readable?}], types: {UDTName: {members: {m: {type, dims?, bit?}}}}, rules: [...effective rule list as configured...], groups: [...]}`.
  `types` comes from ciplink's data_types (UDT templates; hide private and `ZZZZZZZZZZ`-prefixed members; strings
  `{LEN, DATA}` show as type `STRING`). This is what codegen reads.
- `/stats` adds per-group data (section 3) and `writes`, `write_rejects`, `momentary_timeouts`.

## 10. Planner

- **Array runs**: two or more requested elements of one 1-D array of an atomic, non-BOOL type
  (`Arr[3]`, `Arr[4]`, `Arr[7]`) can become one ranged read `Arr[3]{5}`. The values are sliced out. The same cost
  rule as struct groups applies: the extra (unrequested) reply bytes per read saved are at most
  `BYTES_PER_READ`, and the estimated packet count does not grow. Elements inside structs
  (`Tank[2].Level`) are not array runs. They are struct-group territory.
- **together**: `plan(..., together=frozenset of struct paths)`. A requested tag under a `together` struct
  always reads that struct whole (if it is at most the connection size), regardless of cost. If the whole read
  fails, it falls back to members like any group.
- **chunks**: `plan` returns reads in packet order, and `chunks(reads, budget)` splits them into lists of about
  one packet each, for the worker (section 4).

## 11. Mock driver

`--mock` gets realistic: `mock_tags.json` may be the old flat `{name: TYPE}` or

```json
{"types": {"Tank": {"Level": "REAL", "Temp": "REAL", "Valve": "BOOL"}},
 "tags":  {"Tank": "Tank[4]", "Trend": "REAL[16]", "Bench": "BenchData", "Program:Bench.Mode": "DINT"}}
```

- It has `get_tag_info`, `tags`, `data_types`, `connection_size`, so the planner runs in mock mode.
- Reads support members, elements, ranged reads `{n}`, bits and whole structs, returning
  ciplink-shaped `Tag`s with `TagError` kinds.
- Values are deterministic functions of the name and time, shaped by name: `temp` ~ 20-90,
  `level` 0-100, `speed`/`rpm` follows its `SpeedSP` when a `Running` sibling is true, `position` ramps,
  `count` increments, words carry a few toggling bits, and writable setpoints hold their written value.
- Writes are type-checked (BOOL bool or 0/1, ints are ints in range, REAL a number, STRING a str of at most 82
  characters) with kind `bad_value`. Bit writes are read-modify-write.
- `mock_disconnect` support: the worker test helpers can make `open()` or `read()` raise to simulate
  comm loss.

## 12. Client (@ciplink/react 0.3)

- `TagState` gains `error: {kind, message} | null`. Quality `bad` keeps the last value.
- **Refs**: every API that takes a tag name also takes a `TagRef` (from the generated tree or `derive`).
  `String(ref)` is the tag name.
- **Bits from words**: subscribing `X.<n>` (numeric) acquires `X` and computes the bit client-side
  (`(BigInt(v) >> n) & 1`, so LINT works). The server never sees bit subscriptions from this client. Alias
  bits (`X.EStop`) are resolved through `info` bits once known. Until then they are subscribed as given (the server
  resolves aliases).
- **info**: `useTagInfo(name)` returns the info record (section 8) or null. `TagValue` uses `units` by default.
- **Write pre-check**: `store.write` rejects locally (same kinds as the server) when info says not writable or out
  of range. The server stays the authority.
- **derive**: `derive(fn: (get) => T, name?)` returns a `DerivedRef<T>`. Its value is `fn(get)` where
  `get(ref)` returns the current value and records the dependency. Dependencies are tracked again on every
  recompute (conditional reads work). Quality is the worst of its inputs (`bad` > `missing` > `stale` >
  `pending` > `good`). If any input is pending the result is pending. A throw gives quality `bad` with
  `error.kind = "derive"`. Usable in `useTag`, `useTags`, `TagValue`, `TagLamp`.
- **Momentary**: `store.momentary(name)` returns `{press(), release()}`. `useMomentary(ref)`. `<MomentaryButton>`
  presses on pointerdown, holds every 300 ms, releases on pointerup, pointercancel, lost capture, blur and
  unmount.
- **Components**, all fixed size so nothing moves when values, quality or pending state change:
  - `TagValue` and `TagLamp` as today.
  - `NumericInput`: a fixed-width input plus Set button, with an inline confirm step that is reserved
    space, never `window.confirm`, and a fixed-width result slot.
  - `MomentaryButton`.
  - `TagBrowser`: a tree from `GET /tags` (types expanded through `types`). Only expanded rows subscribe (tier 1).
    Each row has name, value, type, RW/RO from info, and a copy button with the path. Large arrays are paged 50
    elements at a time.
- **Typed tree** (`tree.ts`): `tagTree<T>(plc)` is a runtime Proxy that builds names
  (`tree.Tank[2].Level` -> `"PLC1/Tank[2].Level"`, unqualified when generated for a single PLC). Types:
  `TagRef<V, W extends boolean>`, where `useWriteTag`, `NumericInput` and `MomentaryButton` require `W = true`.
  Integer refs have `.bit(n)` and the named alias properties from rules.

## 13. Codegen

`ciplink-tagserver types --url http://host:port --token T [--plc P] --out src/plc.ts` (still accepts the old
`--format names` to emit the name union) reads `/tags` and emits:
- one TS interface per UDT
- a `PLC1Tags` interface of the controller-scope tags plus `"Program:X"` scopes
- leaf types `TagRef<number|boolean|string, W>`, with W true where the effective rule is writable
- arrays as `TagArray<...>` (indexable, `length` literal)
- bit aliases from rules
- `export const PLC1 = tagTree<PLC1Tags>("PLC1")`

The generated file has a header saying it is generated and must not be edited, and gives the tag table version.
Derived values live in user code (`derive`).

## Amendments

Decisions from a review against the 0.2 code, before the parallel implementation. They override the body.

**Terms, config, rules**

1. A *bit name* is a rule `bits` name (`X.EStop`). Logix alias tags (ciplink `alias: True`) are ordinary tags here.
   A *bit* is `X.<digits>`; Logix member names never start with a digit. A bit name resolves only through the
   `bits` of the rules matching `X` (the name minus its last segment), case-insensitively. Unknown names pass
   through unchanged and read as missing, so resolution never fails.
2. `PlcConfig` gains `rules: list[dict]` and `groups: list[dict]`: the raw TOML tables, in file order. `match` may
   be a string or a list in both.
   - Rule keys: `writable`, `min`, `max`, `units`, `description`, `deadband`, `always`, `bits`, `together`.
     Unknown keys are ignored.
   - Group keys: `name`, `rate_ms` (int > 0), `match`.
   - `[server] momentary_timeout_ms` (default 1000) becomes `Config.momentary_timeout_ms`.
3. Token write patterns move from fnmatch to `rules.match`, where brackets are literal. So the 0.2 README advice
   `Arr[[]3]` no longer matches. The README and release notes say so next to the `writable` break.
4. `ciplink_tagserver/rules.py`:
   ```python
   def match(pattern: str, name: str) -> bool        # regex compiled once per pattern
   class Rules:
       def __init__(self, config: Config)
       def effective(self, plc: str, tag: str) -> dict    # merged fields without "match", {} if none;
                                                          # memo on (plc, tag.lower()), cleared past 10000 entries
       def resolve(self, plc: str, tag: str) -> str       # "X.EStop" -> "X.0", anything else unchanged
       def group(self, plc: str, tag: str) -> dict | None # first matching group table
       def groups(self, plc: str) -> list[dict]
       def always(self, plc: str) -> list[str]            # see 9
   ```
   For a bit `X.<n>`, `effective` falls back to `X`'s rules for `writable` only. `min`, `max`, `deadband`,
   `units`, `bits` and `together` never apply to a bit.

**Worker and values**

5. Constructor: `PlcWorker(cfg, factory, cycle_ms, on_values=None, on_status=None, on_meta=None, tier2_period_s=3,
   grace_s=10, planner=True, whole_max_bytes=1500, rules=None, on_info=None)`. `rules=None` means no rules (tests).
   The hub uses these worker members:
   - `write(tag, value) -> Future[(ok, error, kind, value)]`
   - `type_info(tag) -> {"type": str|None, "dims"?: [int]}`, read from the connected driver. A bit is `BOOL`, a
     string struct is `STRING`, `dims` is set only for a whole array, and `{"type": None}` means unknown or not
     connected.
   - `description(tag) -> str|None`
   - `version`
6. `values.py`:
   - `quality(tag) -> str` uses `tag.error_kind`.
   - `error_of(tag) -> {"kind", "message"} | None`.
   - `to_value(tag) -> (value, quality, error)`. The value is jsonable, and only set when the read is good.

   On `bad` the worker keeps the cached value. Stale also keeps the value, and sets error to null. A plain-string
   error is kind `other`, so it reads as `bad`. That is why conftest's FakeDriver and the mock must return
   `TagError(..., ErrorKind.NOT_FOUND)` for missing tags.
7. `refused` and `table_changed` read as `bad` like every other kind, and keep the value. "Transient" only means
   they are not put on the `missing_retry` skip list. That list still holds `missing` tags only.
8. An entry is published when its quality or error changes, or when its value moves past the deadband.
   - The deadband applies only when the last published value and the new value are both int or float (not bool)
     and the quality stays good.
   - Past the deadband means `abs(new - published) >= deadband`.
   - The worker keeps a `published` dict. The cache and the snapshots always hold the latest value.
9. `always` takes literal names only. A rule with `always` whose `match` has `*` or `?` is logged and ignored:
   expanding patterns over members and elements is out of scope. At init the hub sets
   `refs[qname] = Counter({1: 1})` and calls `worker.set_tier(tag, 1)`. Nothing releases it. A reload needs no
   re-add, because tiers survive it. A tag that does not exist reads as missing.
10. Scheduling:
    - Each tier-1 tag has a `rate` (its group's `rate_ms`, else `cycle_ms`) and a `last_read`.
    - `last_read` is dropped when the tag leaves tier 1, so a tag that comes back is due at the next tick. Grace and
      tier 2 ignore groups.
    - `tick = min(cycle_ms, rates of groups that have tier-1 tags)`.
    - A tag is due when `now + tick/2 >= last_read + rate`. Cycle boundaries (tier-2 slice, grace expiry, version
      check) use the same test against `cycle_ms`.
    - An overrun is a tick that takes longer than `tick`.
11. `/stats` changes:
    - Per PLC, `plcs[name].groups = {group: {rate_ms, tags, last_period_ms}}`. `tags` counts the group's tier-1 tags
      now. `last_period_ms` is the time between the group's last two reads, or null.
    - At the top level, `writes` counts writes queued to a worker (momentary included), `write_rejects` counts
      rejections by checks 1-4, and `momentary_timeouts` counts watchdog releases.

**Planner**

12. Signatures:
    ```python
    plan(tags, get_info, whole_max_bytes, no_group=frozenset(), budget=PACKET_BYTES, together=None)
        # together: callable(struct path) -> bool; the worker passes lambda p: rules.effective(plc, p).get("together")
    chunks(reads, get_info, budget=PACKET_BYTES) -> list[list[read]]  # packed like packets(); a fragmented read is alone
    execute(plc, chunks, between=None) -> (results, failed, services)
    ```
    `execute` makes one `plc.read` per chunk. After each chunk except the last, it calls `between(partial)` with
    that chunk's `{tag: Tag}`. Members of failed group reads are read once, after the last chunk. `results` holds
    only the tags not already given to `between`. The existing test now calls `execute(plc, [plan(...)])`.
13. The worker's `between` caches and publishes the partial results first, then runs the queued writes. That way a
    read-back is never overwritten by a value that was read before the write.
14. `together` forces a whole read when at least 2 requested tags are under the struct and its reply fits one
    packet (`structure_size + 10 <= budget - 8 - VERSION_REPLY`). It ignores `whole_max_bytes` and the cost rule.
    It only covers tags read in the same tick. Tier-2 slices in name order usually keep a struct's members together,
    but they don't guarantee it.
15. Array runs: the array is a base tag (`dim == 1`) or a member array (`array > 0`), the index is the last token,
    and the element type is atomic and not BOOL or DWORD. A run is one more candidate in the existing greedy loop.
    A member's path is `[index - start]`. `chunks` and the cost rule size `A[s]{n}` as n elements.

**Writes and momentary**

16. Write checks:
    - Check 1 fails only on a malformed message or a name that does not qualify.
    - Check 2 passes if a pattern matches the qualified name either as sent or after bit-name resolution.
    - Check 3 uses the resolved name.
    - Check 4 skips bools (a Python bool is an int) and non-numbers.

    The hub queues to the worker with no `await` before the queue call, so press and release keep their order.
17. Kinds:
    - Hub: `bad_request`, `not_allowed`, `not_writable` and `out_of_range`, with errors "not allowed", "not
      writable" and "out of range".
    - Worker: ciplink's kinds as they are (`error` is the TagError text). Also `refused` ("PLC not connected" at
      queue time) and `comm` ("PLC disconnected", or an exception from `plc.write`).
    - Client-local: `comm` ("not connected" or "disconnected"), plus `not_writable` and `out_of_range`.
18. Read-back: after a successful write the worker calls `plc.read(tag)`, or `plc.read(tag, word)` for a bit.
    - It caches and publishes the results for names in `tiers`, with no deadband.
    - The ack `value` is the read-back of the written name, or null if that read failed. `ok` stays true either way.
    - Hub API: `async Hub.write(session, name, value, momentary=None) -> (ok, error, kind, value)`.
19. Audit:
    - `tag` is the resolved qualified name, and `old` comes from `worker.snapshot`.
    - `momentary` appears only on momentary lines.
    - One daemon thread drains a `queue.Queue` and flushes after each line. `hub.stop()` drains it.
    - Tests wait for the line count instead of reading the file at once.

    conftest's CONFIG adds `[[plc.<first>.rule]] match = ["Speed*", "Program:Main.Door*"]` with
    `writable = true`, so the 0.2 write tests keep passing.
20. Momentary:
    - It needs `type_info(tag)["type"] == "BOOL"`, which is true for bits. An unknown type (not connected) goes
      ahead and fails like a write. Any other type gets `bad_request`.
    - The watchdog is a `loop.call_later`, keyed by (session, resolved qname) and reset by `press` and `hold`.
    - A `hold` for a tag that is not pressed is ignored, and `id` is optional on `hold`.
    - `press` while already pressed writes true again.
    - A bad `action` gets an `error` message.

**Sessions and info**

21. Several client names can point at one qname (`X.EStop` and `X.0`, or `Speed` and `PLC1/Speed`). So
    `sub["tags"]` becomes `{client name: qname}`, and the index becomes
    `subscribers: {qname: {session: set of client names}}`. Refs count once per (sub, qname).
22. Session state:
    - `send(msg)` for the control queue, a `pending` dict, and an `asyncio.Event` that the sender waits on.
    - Snapshots from `_learn` go to `pending`.
    - `info_sent` holds the client names whose info was sent. Info is a control message, so it goes out before the
      snapshot values.
    - On `meta`, and when the PLC's status becomes `connected`, the hub re-sends info for that PLC's subscribed
      names. The type is only known once the PLC is connected.
23. Every info record has:
    - `type`: a string, or null.
    - `writable`: true only if the rule says `writable` and one of this session's token patterns matches. It can
      differ between sessions.
    - `rate_ms`: the group rate, else `cycle_ms`.
    - `group`: a name, or null.

    `min`, `max`, `units`, `deadband`, `description`, `bits` (on the word) and `dims` (for a whole array, e.g.
    `Trend` -> `[16]`) appear only when set. A bit or a bit name gets `type: "BOOL"`, `writable`, `rate_ms` and
    `group`, and nothing else. A later info for a name replaces its whole record.
24. Descriptions:
    - The worker notes tags that newly enter `tiers` (bits excluded).
    - In the next tick, after the reads, it makes one `get_tag_descriptions(*names)` call if the driver has that
      method. Results are cached per tag table version, with None on error.
    - It then calls `on_info(plc, {tag: description})`, and the hub re-sends those names' full info.
    - A rule `description` wins and goes out at once.

**HTTP**

25. `/tags` returns `{plc, state, version, tags: [{name, type, dims?, aoi_readable?}], types, rules, groups}`.
    - `dims` is `dimensions[:dim]`, present when `dim > 0`.
    - `types` has one entry per `plc.data_types` entry, as `members: {m: {type, dims?}}`. Members come from
      `attributes` when present (ciplink's public members). Otherwise they are the `internal_tags` keys not starting
      with `ZZZZZZZZZZ` or `__`. A member's `dims` is `[array]` when `array > 0`. There is no `bit`: it is layout
      only.
    - String types (`string` set) are not listed. Tags and members of a string type have type `STRING`.
    - An AOI type lists only `aoi.readable` (once probed) and has `aoi: true`.
    - `rules` and `groups` are as configured.
26. Add `CORSMiddleware(allow_origins=["*"], allow_methods=["GET"], allow_headers=["Authorization"])`, because the
    TagBrowser fetches `/tags` cross-origin. The client derives the HTTP base from the ws URL: `ws` becomes `http`,
    `wss` becomes `https`, and a trailing `/ws` is dropped.

**Mock**

27. `mock.make_factory() -> Callable[[PlcConfig], MockDriver]`. The drivers from one factory share a `MockState`
    per PLC name. It holds the written values, `fail` (makes `open()` and `read()` raise CommError) and `clock`
    (`time.time`, which tests can replace). `create_app(mock=True)` makes one factory.

    MockDriver has:
    - `tags`
    - `data_types`, in ciplink shape: `name`, `internal_tags`, `attributes`, `template.structure_size`, and
      `string: 82` for STRING
    - `connection_size = 4000`
    - `_tag_table_version`
    - `get_tag_info`, which raises for unknown names
    - `read` and `write`

    It has no `get_tag_descriptions`.
28. The mock JSON's type syntax is `TYPE` or `TYPE[n]` (1-D), in both `types` and `tags`. A flat-format file
    looks up dotted names whole first. Values come from `zlib.crc32(name)` (not `hash`) and the clock. Writing true
    to `*StartPB` sets the sibling `Running` true, and `*StopPB` sets it false. Other written values hold.

**Client**

29. `TagState.error: {kind, message} | null` and `WriteResult = {ok, error, kind: string|null, value: unknown}`.
    `TagLamp` shows the kept value for `bad` too, with its mark, as TagValue already does.
30. Bits from words:
    - A name matching `/^(.+)\.(\d+)$/` acquires the word at the same tier.
    - The bit's value: for a number, `((BigInt(Math.trunc(v)) >> BigInt(n)) & 1n) === 1n`. For an array (DWORD),
      `!!v[n]`. Anything else gives null with quality bad and kind `bad_request`.
    - Otherwise quality, t and error come from the word.
    - Writes and momentary go to the server as `X.<n>`.
    - `useTagInfo("X.5")` builds `{type: "BOOL", writable, rate_ms, group}` from the word's info.
    - Bit names given as strings go to the server unchanged and are never switched client-side, so the "once known"
      step is dropped. Tree aliases are numeric (31).
31. `tagTree<T>(plc: string | null, meta?: {dims?: Record<string, number[]>; bits?: Record<string, Record<string,
    number>>})`. Meta keys are unqualified paths with each index written as `[]` (`"Tank"`, `"Tank[].Status"`).
    How the proxy builds names:
    - A property `p` appends `.p`. At the root it gives `p`, or `PLC/p` when `plc` is set.
    - Numeric properties append an index, merged as `[a,b]` up to the path's number of dims.
    - `bit(n)` and the names in `bits` append `.n`.
    - `length` returns the dim of that level.
    - `then` is undefined.
    - `toString` and `Symbol.toPrimitive` return the name.

    Members named `bit`, `length`, `then` or `toString` can only be reached with string names.
32. `tree.ts` exports:
    - `TagRef<V, W extends boolean = boolean>`: phantom V and W, plus `toString(): string`.
    - `IntRef<W> = TagRef<number, W> & {bit(n: number): TagRef<boolean, W>}`.
    - `TagArray<T, N extends number = number> = {readonly [i: number]: T; readonly length: N}`.
    - `DerivedRef<V>`: a `TagRef<V, false>` with `derived: true`.
    - `TagName = string | TagRef<any, any>`.

    Strings stay accepted everywhere. Only the TagRef overloads enforce `W = true`.
33. `derive<T>(fn: (get: <V>(ref: TagRef<V, any> | string) => V | null) => T, name?: string): DerivedRef<T>`.
    - An unnamed ref is called `derive:<n>`.
    - Create it at module scope or in `useMemo`.
    - `fn` always runs, so its dependencies are tracked.
    - Any pending input makes the result `{value: null, quality: "pending"}`. Otherwise the quality is the worst of
      bad > missing > stale > good.
    - A derived ref never reaches the server, and `useTagInfo(derived)` is null.
34. Layout and subscriptions:
    - When `unit` is not given, `TagValue` reserves a unit slot of `unitWidth` ch (default 4), filled from info
      `units`. `unit=""` drops the slot. This way a late `info` never moves anything.
    - `NumericInput` takes `min` and `max` from info.
    - TagBrowser rows subscribe at tier 1 like any component. Don't point a `TagLink` at the browser page.

**Codegen**

35. Output and naming:
    - `types --format tree|names` defaults to `tree`. `names` gives the 0.2 output, and test_types passes it.
    - `fetch_tags` returns the whole `/tags` body.
    - UDT interfaces are named `<PLC>_<UDT>` and the tags interface `<PLC>Tags`. Characters that aren't valid in an
      identifier become `_`.
    - With zero or one `--plc`, codegen emits `tagTree<T>(null, META)`, so names are unqualified. With several, it
      emits one tree per PLC, passing `"PLC"`.
36. W is per path: codegen evaluates `rules.match` on the full path, with indexes written as `[0]`.
    - A tag with no writable path anywhere below it uses the shared UDT interfaces, where W is false.
    - A tag with at least one writable path is emitted inline, so W is per path.
    - A rule naming a single element (`Tank[2].Level`) types as not writable. A string write still works.

**Client implementation notes (@ciplink/react 0.3)**

39. A bit's state keeps its previous object, including `t`, while its value, quality and error are unchanged, so
    other bits of the word changing re-render nothing. Its `t` is the time of the bit's own last change.
40. The client does not replace a `bad` value itself: it shows what the server sends, and the server keeps the last
    value (4, 6). A 0.2 server's failed ack (no `kind`) gives `kind: "other"`.
41. Tree meta paths write one `[]` per index group whatever the number of dims: `Grid[1,2].X` is `"Grid[].X"`.
42. `TagBrowser` pages the top-level tag list 50 at a time too, so a large controller does not subscribe every
    top-level tag at once. Struct and array rows never subscribe; only leaf rows on screen do.
43. Planner/mock (task P): `execute` also takes an unsplit plan (a list of reads is one chunk), so the 0.2 worker
    call keeps working. `packets()` now ends the current packet before a fragmented read, as ciplink does, so it
    counts exactly what `chunks` makes. A failed array run goes to `no_group` by its read name (`trend[3]{5}`), and
    an array name in `no_group` stops all its runs. `MockState.fail` also makes `write()` raise CommError.
43. (server core) Two more worker members the hub uses, beyond those in 5: `types` (the `/tags` `types` dict, built
    with `values.type_map(plc)` next to `tag_list` after a connect or reload) and `group_stats() -> {group:
    {rate_ms, tags, last_period_ms}}` for `/stats`. `values.merge(old_entry, tag, t) -> [value, quality, t, error]`
    is the one place that keeps the last value on `bad`. A `[[plc.X.group]]` without a `name` or with a `rate_ms`
    that is not an int > 0 is a config error (ValueError at load), since the scheduler divides by it.
44. (worker, task S2) A tag newly added at tier 2 is read at the next tick, not only on a `cycle_ms` boundary. `type_info`
    gives `BOOL` for a bit even when not connected. After a reload the worker asks again for the descriptions of every
    subscribed tag (the cache is per version), and never asks for a tag whose rule has a `description`. The worker has
    an injectable `clock` (default `time.monotonic`) next to `wait`, so the scheduling tests run on a fake clock.
45. (codegen, task G) Struct and array nodes are refs too, so a whole struct or array can be read: a UDT interface
    `extends TagRef<Record<string, unknown>, false>`, an inline struct is `TagRef<Record<string, unknown>, W> & {...}`,
    and an array is `TagArray<T, N> & TagRef<V[], W>` (W from the rule matching the node's own path). AOIs are plain
    objects (never read whole). Members named `bit`, `length`, `then`, `toString` or `toJSON` are left out of the
    types (31). DWORD is `TagRef<boolean[], W> & {bit(n)}`. An AOI whose type is not in `types` gets its
    `aoi_readable` members as `TagRef<unknown, W>`. Inline (per-path) typing also triggers on rule `bits` below a
    tag, since bit names are per path. `meta.dims` lists every array path, not only multi-dim ones, so `length` works.
46. (example, conformance, task E) The conformance suite also takes `--viewer-token` (a read-only token, for the
    `not_allowed` and `writable: false` checks; skipped without it), and skips the tests that need control of the
    driver (stale, reload) against `--url`. Pass the options with the path: `pytest tests/conformance --url ...`
    (the hook lives in that folder's conftest). The bench tokens are `bench-hmi` (write `PLC1/Bench.*`) and
    `bench-viewer`. Its e2e check is `examples/bench/e2e/bench.e2e.mjs` (`npm run e2e`, playwright-core with the
    installed Chrome). Reading an array tag without an index reads its first element (ciplink, and the mock),
    so the bench shows `Trend` element by element.
47. (review fixes) These override 18, 30, 43 and 45 where they differ.
    - Read-back (18): published unless `published[tag]` already holds it, even when the cache already did (a
      deadband can keep the cache ahead of what was published).
    - Shutdown: the worker runs the writes queued when it stops, then fails any later ones ("server stopping")
      and its state becomes `stopped`. `Hub.stop()` drops the open sessions first. Releases (`disconnect`,
      `timeout`) are queued synchronously, not in a task, and every write is audited from its Future's done
      callback, so a release queued at shutdown is written and audited.
    - A `press` handled after its session was dropped is released at once (`disconnect`), with no watchdog.
    - A momentary release (`release`, `timeout`, `disconnect`) that fails with `comm` or `refused` is kept in
      `Hub.owed` and written again (same `momentary` label) when the PLC's status becomes `connected`; a
      successful press of the tag forgets it.
    - Check 1 also rejects a missing or null `value` and a name with `{` (an element count would match other
      rules than the tag itself). `min`/`max` apply to the written path only: a struct or array written whole
      is checked against its own rule, not its members' rules.
    - `audit_log = ""` turns the audit log off; the audit thread survives any error.
    - `info_sent` keeps only names the session still subscribes, so a name subscribed again gets fresh info.
    - BOOL arrays: ciplink describes `BOOL[n]` (tag or member) as a DWORD array whose dims count 32-bit words.
      `type_info`, `/tags` `tags` and `types` report it as `BOOL` with dims in BOOLs (`* 32`), and an element
      `X[i]` is `BOOL` (so momentary works on it). Codegen then types it `TagArray<TagRef<boolean, W>, N>`.
    - Planner (43): `_pack`/`chunks` put the fragmented reads after all others, as ciplink sorts them, so they
      no longer split the small reads around them. `read_size` sizes `X{n}` of a struct as n structures and of
      a DWORD (BOOL array) as ceil(n/32) words, and `plan` sizes its plain reads with `read_size` too.
    - Mock writes as ciplink: a struct needs every member, an array member of a written struct all its
      elements, and an array written by name without `{n}` one value. Errors show the value as sent.
    - Client (30): a bit's info has no `writable`, since a rule or token pattern can allow the bit and not its
      word; the server decides. `useMomentary` acquires its tag, so `MomentaryButton` gets info. The button
      presses on the primary pointer button only, and on Space/Enter (released on key up and blur).
      `useTags` keys derived refs by identity.
48. (review fixes 2) These override 4, 43, 45, 47 and the body where they differ.
    - Owed releases (47): a release, timeout or disconnect write is owed unless it succeeded or failed with a
      kind a retry never fixes (the hub's check kinds, `not_found`, `access`, `bad_value`), so `table_changed`,
      `device` and `other` are owed too. ciplink 0.2 also answers `refused` while connected (its reload
      backoff, a busy controller), when no `connected` transition comes, so a release failing while the worker
      is connected is written again after `Hub.retry_delay` (0.5 s), until it goes through. Neither a retry nor
      the resend on connect writes a tag that a session holds pressed again.
    - Writes (4): the worker's idle sleep wakes when a write is queued and runs it at once, then sleeps on to the
      same tick deadline, so a write never waits out the rest of a cycle.
    - Check 1 (47): index groups are canonicalised (`[02]`, `[ 2]`, `[+2]` -> `[2]`, as ciplink and the mock
      `int()` them) before rules, token patterns and the worker see the name. An array named without an index
      (`type_info` has `dims`) is a `bad_request`: ciplink writes it as element 0 only, which would skip the
      element rules. A "struct or array written whole" in 47 is only ever a struct, or an `X[i]` element.
    - Codegen (45): an array node is `TagArray<T, N>` only, not a ref, since a bare array name reads and writes
      its first element (46). Use `X[0]` for that element.
    - Pages: learned names of a PLC no longer in the config are dropped at load. `drop()` always releases the
      session's pressed tags and forgets the session, even if an unsubscribe raises.
    - Planner (43): `request_size` sizes the instance segment from the base tag's `instance_id` (16 bits when
      unknown), and `_pack` counts the standalone version check before and after each read sent alone (the
      worker sends each in its own `plc.read`), so a merge that turns fragmented is not taken for free.
    - Mock: struct member names in a written value are case-sensitive and a REAL must fit a float32, as ciplink.
    - Client: `store.get(derived)` of a ref nobody listens to or acquires computes it on the spot and keeps no
      entry or input listeners (they would never be disposed). The lamp is `role="img"` with its state as
      `aria-label`; the NumericInput result and MomentaryButton error slots are `role="status"` live regions
      that the input or button points at with `aria-describedby`. Cancel returns the focus to the input.
